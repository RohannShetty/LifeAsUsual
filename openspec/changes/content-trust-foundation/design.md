# Content trust design

## Current baseline
- `data/en-in/chapters/*.json` stores inherited India-adapted tips.
- `data/en-in/manifest.json` stores chapter-level status, fixed 34/765 counts, source count and human review.
- `scripts/verify-india.ts` checks structure, a subset of source URLs and recorded reports.
- `src/components/TipCard.astro` shows "Checked" for AI-checked tips, potentially overclaiming.
- User reading ledger persists IDs such as `13-1` in browser `localStorage`.

## Target entities
1. **Lesson**: stable opaque key, slug, category, audiences, origin, sourceEditionId (optional), canonical claim IDs, risk level, review status and published revision.
2. **SourceReference**: unique ID, canonical URL/DOI/document identity, title, publisher, publication/update date, snapshot/access date, language, license and content location.
3. **ClaimEvidence**: stable claim ID, canonical lesson ID, claim text, supporting source IDs with exact page/section/paragraph, study population, jurisdiction, applicability limits, evidence strength, independently assessed result and verifier artifact.
4. **JurisdictionOverlay**: country `IN`, state/UT code or national scope, effective period, exact administrative rule, linked claim and official primary source.
5. **LocaleVersion**: BCP-47 locale, canonical lesson/revision, translated copy, reviewer, number/negation checks, publish status and fallback disclosure.
6. **VerificationEvent**: time, actor/role, method, source fetch outcome, claims checked, findings, source snapshots/digests (where licensed), approval/rejection and audit hash or commit.

## Status semantics
- `unverified`: evidence missing, inaccessible or not yet reviewed; cannot be presented as verified.
- `ai-reviewed-draft`: independent AI checked exact accessible cited sources for a specific version and no unresolved blocking finding; **not** professional approval. Visible on reader card.
- `human-reviewed`: named qualified reviewer signed off with scope/date.
- `withdrawn`: outdated or incorrect recommendation; withheld from recommended content while corrections remain linked.

Evidence grade A/B/C and editorial status are independent. A grade A study from another country does not establish an India-specific legal or medical claim.

## Publication rules
- Fail closed for known harmful or unsupported high-risk claims; publish a safe official-resource fallback if appropriate, not hallucinated instructions.
- A source URL is necessary but insufficient; official homepage links do not count as support for detailed claims.
- Track source access failures and claim-to-source mismatch as explicit failures.
- Do not auto-approve text generated by the writer with the same unchecked context.
- Preserve version/reviewer traceability for corrections, including new references.
- Never represent a translation as reviewed merely because its English source version passed.
- Surface state coverage status honestly; do not infer rules for an unverified state.

## Migration plan
1. Add versioned JSON schema and authoring types alongside existing chapters; use additive metadata first.
2. Introduce pilot evidence records and a verifier that validates exact per-claim references.
3. Update display labels to explicitly distinguish AI draft and human-reviewed states, keeping legacy fields in a compatibility adapter.
4. Add original India lesson namespace (e.g. `in-...`) without changing legacy `chapter-tip` anchors.
5. Introduce jurisdiction overlays and locale variants with explicit completeness/fallback metadata.
6. Relax hard-coded 34/765 release rules only after preserving legacy count checks for the inherited edition.
7. Expand the model in small audited batches and reconcile the generated files with authoritative overrides.

## Reader and accessibility
Status text must be visible without tooltips and readable to screen readers. Provide exact official source links on demand. Display a warning when a claim has not been checked recently or is outside the user's selected jurisdiction.

## Non-functional constraints
Static Astro build remains usable without network at read time. No new mandatory account, analytics tracker or reader-data server. Content and workflow changes must not break Pagefind index, text rendering, old bookmarks or browser ledger migrations.
